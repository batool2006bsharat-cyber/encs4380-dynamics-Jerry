Digital PID: what the Arduino really does

Module P3: Digital PID

A microcontroller cannot watch the output all the time. Every Ts seconds it reads the sensor once, computes one new control value, and holds it until the next sample. The plant keeps moving in between, so the controller is always working with slightly old information. A small Ts behaves like the continuous PID from P1. A large Ts adds delay, so the overshoot grows until the loop can no longer settle.

u[k] = Kp e[k] + Ki Ts Σj=0..k e[j] + Kd (e[k] − e[k−1]) / Ts,   then u is held constant until sample k + 1.

Apply it to the Micromouse motor

Micromouse groups must find K and τ of the drive motor from a PWM step test logged with the encoder, then design the speed loop with 0.6 ≤ ζ ≤ 0.8 and a PWM command that stays within 0–100 %. These three steps do exactly that.

Counts per revolution = encoder lines on channel A × gear ratio (the code counts rising edges of channel A only). Check your motor's datasheet.

1. Run the step test

Lift the wheels off the table, upload this sketch, open the Serial Monitor at 115200 baud and copy everything it prints.

2. Paste the log to find K and τ

3. Design the speed loop and copy its code

Choose “Micromouse motor” under Plant (or press “Use these values”). Then press the button below for a starting PI design with ζ = 0.7, check that the PWM stays under 100 % at your Ts, and copy the code from “Arduino code” above: in this mode it reads the speed from the encoder and writes the PWM in %.

How the suggestion works: with Kp = 1/K the term (1 + KKp)/τ equals 2/τ, so 2ζωn = 2/τ gives ωn = 1/(ζτ), and ωn2 = KKi/τ gives Ki = 1/(ζ2τK). These are the same PI formulas as validation check 2.
